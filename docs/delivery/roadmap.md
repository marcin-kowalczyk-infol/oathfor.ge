# Delivery roadmap

Status: proposed sequence without dates, budgets or commercial forecasts. Source: [product brief](../product/brief.md).

| Gate | Deliverable | Exit evidence |
| --- | --- | --- |
| 0 — Foundation | Shared docs, roles, skills, monorepo conventions | Repository checker passes |
| 1 — Loop specification | One Oath template, proof rules, recovery and state transitions | Happy path and failure scenarios can be explained without ambiguity |
| 2 — Visual identity | Companion references and progression concepts | Consistent identity across unseen poses/states at mobile size |
| 3 — Vertical slice | Commit → intervene → submit → resolve → recover | Real mobile/API flow, retries and permission checks |
| 4 — Squad loop | Invites, feed and shared objective | No duplicate progress and no accidental proof sharing |
| 5 — Instrumented alpha | Events, support path, backups and provider failure handling | Cohort can complete the loop and failures can be diagnosed |
| 6 — Release candidate | Subscription, operational readiness, store packaging | Relevant tests and restore/reconciliation exercises pass |

Scope counts, cohort size and schedules are not commitments. First-user recruitment strategy and monetization experiments belong in `business-plans/`; event definitions remain in [analytics](../product/analytics.md).
